# pi-web-simple：给 pi 加一个本地 Web UI

pi 的终端界面我一直用着挺舒服，但有几件事在终端里做起来别扭：

- 它一边改文件，我想一边点开某个文件看看改成什么样了，而不是等它跑完再 `git diff`
- 同时开着五六个会话，想一眼看出哪个在跑、哪个在等我
- 想看看这一轮动了哪几个文件，而不是在 scrollback 里往上翻
- 有些决定它自己就拍了（用哪个库、范围划到哪），我想在它动手之前先看一眼

所以就动手写了这个：**pi-web-simple**，一个本地 Web UI，pi 还是那个 pi，只是在外面套了一层壳。

![主界面](https://cdn.jsdelivr.net/gh/woxihejinghao/pi-web@main/docs/images/overview-light.png)

## 它是什么

一句话：**一个本地目录 = 一个项目**，项目下挂这个目录的会话，agent 内核是 pi 本身，通过 `pi --mode rpc` 子进程接进来。

几个设计上的选择，我觉得挺关键：

- **会话列表不是另存一份。** 页面里的列表是实时从 pi 自己的存储里读出来的，你在终端 `pi --resume` 看到的会话和页面里的是同一批，不会出现「两边各有一份记录」的情况。
- **每个会话一个 pi 进程，懒启动 + 空闲回收。** 不打开的会话不占资源，打开过的放在那儿待命。
- **界面是照着 deepseek-harness 做的。** 左栏工作区，中间对话，右栏文件 / 变更 / 终端 / 浏览器，用惯 dsh 的话基本不用重新学。

## 一次会话一种组成：极简模式

这是从 dsh 的 agent preset 抄来的：新建会话时除了选模型，还能选**模式**。

「极简模式」会把整个系统提示固定成一句话（`You are a helpful software engineer assistant.`），模型能看到的工具只剩一个 `bash` —— 上下文文件、技能、MCP、扩展、提示词模板全都不加载。适合那种「就跑一个脚本、别多想」的任务，也适合压 token。

![新建会话页的模式选择器](https://cdn.jsdelivr.net/gh/woxihejinghao/pi-web@main/docs/images/mode-picker-light.png)

有一件事值得说：**它只能在创建会话时选，之后改不了**。这不是偷懒——pi 没有改工具集或系统提示的 RPC（`set_tools` / `set_system_prompt` 都不存在），所以一个「组成」只能表达成启动参数。这恰好等于 dsh 的规则：会话一开始对话，它的组成就固定了。只是 dsh 把它记在会话日志里，这里记在进程上。

`/web` 是唯一被单独留下的扩展：`--no-extensions` 是唯一能把 `todo` 和 `ask-user` 一并去掉的开关，但 Web UI 本身是这个部署的入口，得留着（dsh 在极简组成里也留着自己的平台 shell，同一条道理）。

顺带一提，已存在的会话是从**文件里**反推出它是什么组成的——pi 会把第一个请求的提示段落和工具声明写进会话 JSONL 的首条 system message，那正是 dsh 存进 `agentPreset` 投影的同一份证据。所以打开一个极简会话时，它会用极简的参数去启动，而不是拿默认组成去接。

## 让它先问，再动手

pi 自己有 `ask_user_question`，但这里做成了 dsh 的形状：**一次调用带一整批问题**，在一张卡里逐题答完、一次提交。选项有说明、可以多选，也可以只有自由文本。

有个坑挺绕：pi 的 UI 子协议只有 `select` / `confirm` / `input` / `editor` 四种**单问题**对话框，没有批量形态。所以批次被编码进 `select` 的 title（一个前缀标记），由服务端在入站时解包——浏览器看到的是干净的 `questions` 数组，回答时再打包回 pi 期待的那个值。翻译只发生在这一段。

**超时不等于「用户拒绝了」。** 卡片的截止时间到了，它会主动上报一个 pending，而不是让 pi 把沉默记成跳过；问题留在牌桌上，你过一会儿回来还能回答。判定不看内存状态，而是从转录里投影出来的，所以刷新、压缩、分叉之后结论都一样。

还有一种是**计划审批**：如果这个问题带了 intent（「批准」是哪个选项），卡片不再画选项列表，而是渲染成一张审批卡——一条「计划审批」的条、计划全文（默认两行，展开才铺开）、两个动作：请求修改 / 批准。批准回传的就是模型自己给的那个标签，原样显示不翻译，因为回传的确实是那个字符串。

对了，答案批次和提问对不上时（少答一题、多个未知 id）会直接拒收。那种情况在模型眼里和「用户跳过了」长得一模一样，把默许传下去比报错更糟。

## 输入框里现在有三样东西

打 `@` 会弹出候选，来自 `git ls-files`（已经被 `.gitignore` 过滤过，agent 找不到的文件也不会出现在菜单里），选中之后路径作为一个 chip 落进句子。

要注意的是**插进去的是路径本身，不是文件内容**：pi 的 RPC 模式没有 `@file` 语法，下游没有任何东西会展开它。模型拿到的是一句话加一个路径，用自己已有的 read 工具去打开——这样行号、图片处理、截断策略都还是 pi 自己那套，上下文环的数字也不会因为一次引用悄悄涨一截。

![输入框里的 @ 引用菜单](https://cdn.jsdelivr.net/gh/woxihejinghao/pi-web@main/docs/images/file-mention-light.png)

第二样是**模型和思考强度合成的一张卡**（样式照 Codex 来）。用一个滑块而不是第二个下拉菜单，是因为档位本来就有序——位置同时说出了「在哪一档」和「还剩几档」。拖动时只在本地预览、松手才提交，横跨五档的一次拖动是一次选择，不是五次往返。

![模型与思考强度卡片](https://cdn.jsdelivr.net/gh/woxihejinghao/pi-web@main/docs/images/model-card-light.png)

第三样是那枚上下文读数的 chip，点开是「窗口 / 已用 / 剩余」。它和模型 chip 用同一套内边距和字号——两个控件描述的是同一个会话、会被一起读，配方不同就会读成两个来源。

## 改了名字，终端里也是新名字

会话重命名是追加进 pi 会话文件里的 `session_info`，不是在 Web 这边另存一个覆盖项。

这件事看起来小，但它决定了「这个会话叫什么」只有一个答案。我在页面里把某个会话改叫「修登录超时」，回到终端 `pi --resume`，它就叫这个名字。反过来也一样。

## 右栏是能干活的地方

文件树、预览、Git 变更、终端、内嵌浏览器都在右栏，而且能分成左右两格，标签也能拖出来变成浮窗。

预览不只是文本：Markdown 会渲染，代码走 shiki 高亮，图片、PDF 直接看，HTML 是 `sandbox=""` 加一条 CSP 的静态预览，脚本一律不跑。

Git 那一格是完整的：看每个文件的 diff、暂存、提交、推送、切分支，不用切回终端。每一轮对话的末尾还会有一张「本轮改动」卡片，点开是这一轮改动的完整面板，左边选文件、右边看带行号的 diff。

![右栏的终端](https://cdn.jsdelivr.net/gh/woxihejinghao/pi-web@main/docs/images/promo/terminal.png)

终端是真的 PTY（xterm.js + node-pty）。有个细节我特意做成了这样：**关掉标签页才会杀掉那个 shell**，折叠右栏、切会话、刷新页面都只是断开，重新打开还在原来的地方接着看。后台跑着的构建不会被收起侧栏掐断。

右栏常用的几个动作有全局快捷键，绑定是直接从 dsh 抄的（`⌥⌘B` 收起右栏、`⌘P` 打开文件、`` ⌃` `` 新开终端……），两个应用之间的肌肉记忆能通用。

## 设置页写的是 pi 自己的文件

模型、插件、MCP 三节改的都是 pi 自己读的那几个文件（`models.json` / `auth.json` / `mcp.json`），不是这里的私有配置，所以页面里配好之后终端里的 pi 直接就能用。MCP 那节按 pi 自己的合并规则读写全局和工作区两份 `mcp.json`。

模型目录里还能直接编辑：给某个模型勾上「支持推理」、标出 `xhigh` / `max` 这类提供方专属档位、改上下文窗口和最大输出、勾选输入类型。这些以前只能手改 `models.json` 才能生效。

## 顺手修掉的两个卡顿

- **一次切会话不再解析两遍 JSONL。** `/messages` 和 `/composer` 同时到达，本来各自打开同一个文件，那次解析就在服务端唯一的线程上跑了两遍。现在按「文件大小 + mtime」缓存刚解析好的会话，后一条请求复用。带图会话（31MB payload）实测 `/composer` 37ms → **1ms**。
- **工具结果里的图片不再随转录一起传。** 截图多的会话，一次切换要把整条会话的 base64 全塞进一个响应——15 到 31MB，浏览器得先 parse 完才能画出第一行。现在转录里换成按需取的 URL。200 轮 / 15MB 工具图实测 `/messages` 15.2MB → **0.2MB**，首帧 280ms → **133ms**。

## 已知的坑

先把不好听的说完：

- **只监听 `127.0.0.1`，没有登录也没有鉴权。** 它是给自己电脑用的，别往外网放。
- **终端标签依赖可选的 `node-pty`**（原生模块）。平台没有预编译二进制时（比如 Linux）要本机编译；装不上只有那一个标签置灰，其余功能不受影响。
- **极简模式跑过一轮就改不了**（上面说的那个原因）。空会话还能从会话头部换回标准组成，一旦说过话，就只能新建一个会话。
- **问答卡片跨刷新的草稿有，跨会话的补答入口也在，但一批问题只能答一次**——答完就归档进转录，改不了。
- **失败的那一轮只能「把这条 prompt 再发一次」，没有真正的重试。** pi 的重试循环只在 turn 内部跑，RPC 里没有对应入口。
- **变更面板没有左右对比视图**，HTML 预览也永远不跑脚本（这是刻意的，不打算加开关）。
- **桌面版还没有代码签名**：macOS 第一次打开要右键 → 打开，Windows 会弹一次 SmartScreen。
